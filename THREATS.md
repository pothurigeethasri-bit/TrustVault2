# THREATS.md: what can go wrong, and how TrustVault defends

Method: for each asset (documents, accounts, the audit trail) I asked "who might attack it, how, and what stops them?". Each defence names the code that implements it and the automated test that proves it. Run the tests with `pytest` (see README); the database tests need `TEST_DATABASE_URL`.

**Assets:** (1) document contents, (2) user accounts and roles, (3) the audit trail.
**Attackers considered:** an anonymous visitor; a logged-in viewer or owner trying to reach what is not theirs; a user whose access was just revoked; a malicious uploader; an admin account being misused; someone with direct database access.

## 2. Known limitations (honest list)

These are not defended, or only partly. I would address them with more time:

- **Audit log is tamper-evident, not tamper-proof against the database owner.** Someone who can disable triggers and recompute every later hash could forge a clean chain. A fix is to publish the latest hash somewhere outside the database on a schedule.
- **The restricted DB role may be unavailable on a managed host.** If the host does not let the owner create roles, only the triggers and hash chain protect the log.
- **No multi-factor authentication.** The security PIN is a shared perimeter secret, not per-user MFA.
- **Password reset is admin-mediated** (there is no e-mail system). The temporary password must be handed over through a private channel.
- **Username lockout can still be abused**: someone who knows a username can lock it for 15 minutes (an admin reset clears it). IP limits depend on `TRUST_PROXY=1` behind Render; behind other proxies the IP may be wrong.
- **The PIN is shared.** Anyone who learns it can reach the login page; rotate it by changing `ACCESS_PIN`.
- **Open self-registration.** Anyone can create a viewer account (they see nothing until shared with). There is no email verification.
- **No antivirus scanning.** Uploads are type-checked, not malware-scanned. They are served as attachments with `nosniff`, but PDFs, images and text open inline in the browser.
- **Whole files are read into memory** (10 MB cap), fine for this scale but not for large files.
- **Integrity check reads the whole log**, so it gets slower as the log grows.
- **Free-tier hosting limits.** Render's free database is deleted after a trial period and the free web service sleeps when idle; use a paid plan for anything real.
